RAG Against the Machine

Your pipeline never hands the vLLM repo to Qwen. It cuts files into ≤ 2,000-character chunks that remember their file and character range, BM25 ranks them by shared rare terms, and only the top-k ranges, re-read from disk, go into a token-budgeted prompt.

Question

Files: a miniature, made-up corpus shaped like vLLM (the real repo is far too big to show). The chunking, tokenizing, BM25 ranking, top-k, prompt building and Recall@k are your code's algorithms re-implemented here, and checked against your actual Python for these files. Equal scores may be listed in a different order than bm25s, which breaks ties arbitrarily. Not reproduced: Qwen's real token counts (estimated as ≈ characters ÷ 3.6) and Qwen's answers (illustrative).

What to notice

  • Chunk: drag the max size down. Python cuts land after a def/class, docs cuts at headings and blank lines; when nothing fits, it falls back to a line break (red).
  • Tokenize: block_size becomes block_siz + block + size, so both "block_size" and "block size" match.
  • Chunk README.md at 400: the ## Quark heading lands at the end of chunk 1, because the blank line after it is a farther boundary. Chunk 2 is still found for "Quark" thanks to its heading path Quantization Quark, which is indexed with it (see Score).
  • Top-k: type just vllm. It's a stop word, so nothing scores, and you still get k results.

You might think…

…that the index hands Qwen the text it found. It doesn't: search returns only file path + character range (that's what the grader scores). answer then re-opens each file and slices text[first:last], which is why the loader keeps line endings exactly as written.
